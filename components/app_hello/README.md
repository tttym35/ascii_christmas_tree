# ASCII Christmas tree controller

The device and native simulator share the projected ASCII scene, depth buffer, touch hit testing and 33 ms timer. The GSP canvas uses the 480 × 480 RGB565 profile. Objects closer to the viewer own the touch target in each visible cell. A horizontal drag turns the tree and pushes the snow near the finger path; the star sends light down the helix.

Tree materials (six kinds, at most four on the tree) and the two ground gift boxes are one material system: whole-material hiding behind the tree, spaced respawns only while auto-rotating, a shared screen particle layer, and per-kind interactions. Interactions report `app_hello_effect_t` through `app_hello_set_effect_handler`; the scene never touches hardware, so sound and vibration live in the composition root. The volume panel (music and effects sliders) is toggled with `app_hello_toggle_volume_panel`, which only sets a flag and is safe from any task (the board's AI key callback); the next UI tick applies it. Each touch's owner is decided where it first presses: inside the open panel the sliders keep it through release (sliding out does not close the panel); outside the open panel it closes the panel and is ignored through release; otherwise it goes to the tree. Slider changes reach `app_hello_set_volume_handler` as `(music, sfx)` on the UI loop.

Call `app_hello_create(ui, &controller)` once after starting GSP. The controller borrows the UI and owns its pointer observer, canvas draw callback and timer. Rendering and input run on the UI loop. Read diagnostic snapshots on that loop or once dispatch stops. Quiesce dispatch before destroying the controller and keep the borrowed UI alive until cleanup completes.
